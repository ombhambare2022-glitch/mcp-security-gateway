Background

MCP — and why the naive setup breaks down

◈

What is MCP?

The Model Context Protocol is an open standard that lets AI agents discover and call external tools — mail, chat, code, files — over one common interface.

A client connects to servers such as:

Gmail Slack GitHub Drive

Each server advertises its tools as JSON schemas, which the agent loads into its context window.

⚡

Why direct connection breaks down

Linear context growth

Every new server adds its full tool list upfront — cost grows with N servers × M tools.

Attacker-controlled text

Descriptions and results flow straight into the prompt — a classic injection channel.

No policy layer

Nothing checks parameters or outputs between the agent's intent and the live API call.

Solution: It answers both with one gateway — six meta-tools for a fixed context cost and four security gates for defense in depth.

Problem Statement
Key Challenges

Agents are drowning in tools they can't trust

◎

Context bloat

  • Every connected server preloads all of its tool schemas into the agent's context
  • Dozens of servers × dozens of tools burn thousands of tokens before work even starts
  • A bloated context slows reasoning and degrades tool selection
⚠

Prompt injection

  • Tool descriptions and API results are third-party, attacker-reachable content
  • A poisoned description or result can silently redirect the agent's behaviour
  • One hijacked call can leak mail, files, or credentials
